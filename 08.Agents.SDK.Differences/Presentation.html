Context

Why do two frameworks exist?

They were built for different levels of the stack and different audiences — but both are from Microsoft and both ship on NuGet.

Microsoft.Extensions.AI (ME.AI)
A low-level abstraction layer over any LLM SDK
Defines IChatClient — the common interface all providers implement
Middleware pipeline: UseFunctionInvocation(), UseOpenTelemetry(), caching, etc.
You control every step of the tool-call loop
Directly comparable to ASP.NET Core middleware — composable, explicit
Target: library authors, platform teams, anyone building on top of AI
Microsoft Agent Framework (MAF)
A higher-level agent runtime built on top of ME.AI
Introduces AIAgent — an opinionated agent with instructions, tools, and a managed run loop
Tool-call loop is owned internally — you just call RunAsync()
Designed for multi-agent orchestration and enterprise agent workflows
Part of a larger ecosystem (Bot Framework, Copilot Studio, Teams AI)
Target: application developers building agent-first products

Architecture

How they relate

MAF is not a replacement for ME.AI — it depends on it. You still get the IChatClient pipeline under the hood.

Microsoft Agent Framework (MAF) — AIAgent.RunAsync()
↕ built on top of
Microsoft.Extensions.AI — IChatClient pipeline
↕ wraps
Azure.AI.OpenAI
AzureOpenAIClient
OpenAI SDK
OpenAIClient
Other providers
Ollama, Gemini…
ME.AI provides the infrastructure. MAF provides the agent runtime. You can use ME.AI without MAF, but not MAF without ME.AI.
Code Comparison

Building a chat client — side by side

Sample 05 · Microsoft.Extensions.AI
IChatClient chatClient =
  new AzureOpenAIClient(uri, key)
    .GetChatClient(deployment)
    .AsIChatClient()
    .AsBuilder()
    .UseFunctionInvocation()
    .UseOpenTelemetry(o => ...)
    .Build();

// Pass tools in ChatOptions each call
var options = new ChatOptions
{
  Tools = [tool1, tool2, tool3],
  ToolMode = ChatToolMode.Auto
};

var response = await chatClient
  .GetResponseAsync(messages, options);
Sample 07 · Microsoft Agent Framework
AIAgent agent =
  new AzureOpenAIClient(uri, key)
    .GetChatClient(deployment)
    .AsIChatClient()
    .AsBuilder()
    .UseOpenTelemetry(o => ...)
    .Build()
    .AsAIAgent(
      instructions: systemPrompt,
      name: "my-agent",
      tools: [tool1, tool2, tool3]);

// Tools registered at construction
// No ChatOptions, no loop management
AgentResponse r =
  await agent.RunAsync(userPrompt);

Observability

OpenTelemetry — what you get from each

Both emit gen_ai.* spans because MAF delegates to the ME.AI IChatClient under the hood. The difference is where you wire it.

Signal ME.AI (Sample 05) MAF (Sample 07)
gen_ai.chat spansOne per model call, from UseOpenTelemetry()Same — middleware sits below AsAIAgent()
Token usage metricsgen_ai.client.token.usage via ME.AI meterSame meter, but RunAsync() doesn't return totals
Prompt/completion contentEnableSensitiveData = true captures bodiesSame flag, same behaviour
Activity sources to registerMicrosoft.Extensions.AI + Experimental.*Identical — MAF re-uses ME.AI sources
Custom parent spanappSource.StartActivity("run-ai-agent")Same pattern recommended
Tool calls visible in tracesYes — as child spans of each model callYes — same mechanism
Bottom line: App Insights traces look virtually identical between the two samples. The primary OTel difference is that MAF does not surface token totals on the response object — you must read them from the OTel metrics or use streaming.
Decision Guide

When to use Microsoft.Extensions.AI

✅ Choose ME.AI when…
You need full control over the message loop (e.g. streaming, token budgets)
You want to inspect or modify every message before/after each model call
You're building a library or platform component others will consume
You need token usage surfaced on every response (response.Usage)
You want a lightweight dependency — no agent runtime overhead
You're routing through APIM and need per-call header control
You want to swap providers (Azure OpenAI → Ollama → Gemini) without code changes
Typical pattern
IChatClient client =
  provider
    .AsIChatClient()
    .AsBuilder()
    .UseYourMiddleware()
    .UseFunctionInvocation()
    .UseOpenTelemetry(...)
    .Build();

var r = await client
  .GetResponseAsync(msgs, opts);
// r.Usage.InputTokenCount available
Sample 05 and Sample 06 in this workspace both use ME.AI — including when going through APIM.
Decision Guide

When to use Microsoft Agent Framework

✅ Choose MAF when…
You want an opinionated agent object with identity (name:, instructions:)
You're building multi-agent systems where agents hand off to each other
You want the tool-call loop fully managed — just call RunAsync()
You plan to integrate with Bot Framework, Teams AI, or Copilot Studio
You want a higher-level API that feels like a product, not a pipeline
You don't need fine-grained token accounting per response
Your team is already invested in the Microsoft AI Platform ecosystem
Typical pattern
AIAgent agent = provider
    .AsIChatClient()
    .AsBuilder()
    .UseOpenTelemetry(...)
    .Build()
    .AsAIAgent(
      instructions: prompt,
      name: "my-agent",
      tools: [t1, t2]);

AgentResponse r =
  await agent.RunAsync(input);
// r.Text — full answer
Sample 07 in this workspace uses MAF — AsAIAgent() on top of the same ME.AI IChatClient pipeline.
Summary

The short version

Question ME.AI answer MAF answer
What is it?A composable middleware pipeline around IChatClientAn opinionated agent runtime built on ME.AI
Who's in control?You — every step is explicitMAF — RunAsync() handles the loop
Token usage on response?Yes — response.UsageNo — read from OTel metrics instead
Multi-agent support?Roll your own orchestrationFirst-class — designed for it
Best for…Control, libraries, APIM, provider-agnostic appsAgent products, Teams/Bot Framework, Copilot Studio
Rule of thumb: Start with ME.AI if you want maximum flexibility and observability control. Graduate to MAF when you want a higher-level agent runtime with built-in loop management and multi-agent support — knowing that it sits on top of ME.AI and all the same OTel infrastructure applies underneath.
