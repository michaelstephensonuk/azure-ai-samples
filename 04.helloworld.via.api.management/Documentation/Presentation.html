Key Decision

Why use OpenAIClient instead of AzureOpenAIClient?

This is the most important architectural choice in this sample:

ClientURL it constructsAPIM match?
AzureOpenAIClient {endpoint}/openai/deployments/gpt-4o/chat/completions ✗ 404 — APIM operation not found
OpenAIClient {endpoint}/chat/completions ✓ matches APIM operation path

APIM's inbound policy then rewrites the URL from /chat/completions → /openai/deployments/gpt-4o/chat/completions?api-version=… before forwarding to Azure OpenAI.

Key Code

Building the client with APIM transport

// HttpClient carries the APIM subscription key on every request
var httpClient = new HttpClient();
httpClient.DefaultRequestHeaders.Add(
    "Ocp-Apim-Subscription-Key", apiKey);

var options = new OpenAIClientOptions
{
    Endpoint = new Uri(endpoint),   // ← APIM gateway URL
    Transport = new HttpClientPipelineTransport(httpClient)
};

IChatClient chatClient = new OpenAIClient(
    new ApiKeyCredential("placeholder"), // key already in headers
    options)
    .GetChatClient(deploymentName)
    .AsIChatClient()
    .AsBuilder()
    .UseOpenTelemetry()
    .Build();
APIM Setup · Step 1 of 4

Add a Language Model API

In the Azure portal, navigate to your APIM instance → APIs → + Add API. Under Create an AI API, choose Language Model API — this template pre-configures the OpenAI-compatible passthrough and token policies.

APIM Setup · Step 2 of 4

Configure the API

Fill in the display name, set the Path (e.g. samples/azure-open-ai), and choose Create a passthrough API. Enter your Azure OpenAI endpoint URL and the API key under Access key. The key is stored securely in APIM — your client app never sees it.

APIM Setup · Step 3 of 4

Manage token consumption

On the Manage token consumption tab, set a Tokens per minute limit (e.g. 1000 TPM) and enable Track token usage. Select your Application Insights instance — APIM will emit token metrics automatically via the llm-emit-token-metric policy.

APIM Setup · Step 4 of 4

Enable Diagnostics Logs → Application Insights

Under the API's Settings → Diagnostics Logs, enable the Application Insights destination, set sampling to 100%, and choose Information verbosity. This ensures every APIM request is correlated with your OpenTelemetry traces in the same App Insights instance.

APIM Result

Auto-generated inbound policies

Once created, the API portal shows the policies added automatically: set-backend-service llm-emit-token-metric llm-token-limit. Click + Add policy to add custom policies (e.g. rewrite-uri to prepend the deployment path).

APIM Policy Detail

Full inbound policy XML

The policy editor shows the complete configuration. Key highlights: the rewrite-uri expression dynamically prepends /openai/deployments/{{AzureOpenAI-DeploymentName}}/ to any path, and set-query-parameter enforces the correct api-version — keeping all routing logic out of the client application.

APIM Setup · API Settings

API Settings — subscription key & URL suffix

In the API Settings tab, confirm the API URL suffix (e.g. samples/azure-open-ai) and note the Subscription section — Subscription required is checked and the Header name is Ocp-Apim-Subscription-Key. This is the header your client code must send instead of the Azure OpenAI key.

APIM Setup · Backend Auth

Backend authorization — Azure OpenAI key via Named Value

Under the backend's Authorization credentials → Headers tab, APIM injects the api-key header on every outbound request to Azure OpenAI. The value references a Named Value — the real key is stored securely in APIM and is never visible to the client application.

APIM Inbound Policy

What APIM does on every request

1
Validate subscription key — rejects callers without a valid Ocp-Apim-Subscription-Key
2
Rewrite URL — prepend /openai/deployments/gpt-4o to the incoming path
3
Add api-version — appends ?api-version=2024-02-01 query parameter
4
Inject api-key header — reads the Azure OpenAI key from a Named Value (never sent to the client)
5
Remove subscription key — strips Ocp-Apim-Subscription-Key before forwarding to the backend
App Insights KQL · APIM Requests Table

Token usage by hour — per API and subscription

APIM writes a Response-Body custom dimension to the App Insights requests table. This KQL query parses the OpenAI usage object from the response body to aggregate token consumption by hour, broken down by API name and APIM subscription — giving you a centralised cost view across all callers.

// App Insights: requests table (written by APIM diagnostics)
requests
| extend total_tokens_ = toint(
    parse_json(
        tostring(
            parse_json(
                tostring(customDimensions.["Response-Body"])
            ).usage
        )
    ).total_tokens)
| where total_tokens_ > 0
| extend API_Name_          = tostring(customDimensions.["API Name"])
| extend Subscription_Name_ = tostring(customDimensions.["Subscription Name"])
| summarize sum(total_tokens_)
    by bin(timestamp, 1h), API_Name_, Subscription_Name_
Why this works
APIM's diagnostics policy logs the full response body to App Insights. The customDimensions["Response-Body"] field contains the raw OpenAI JSON, so parse_json() can extract .usage.total_tokens directly.
What you get
A time-bucketed table of total tokens grouped by APIM API and subscription name — enabling chargeback, budget alerts, and per-team usage dashboards across every client that calls through the gateway.
Why Add APIM?

Benefits of routing AI calls through API Management

🔑 Key Security
  • Azure OpenAI key never leaves APIM
  • Clients authenticate with APIM subscription keys only
  • Keys can be rotated in one place — zero client changes
  • Fine-grained subscription scoping per product/team
📊 Centralised Observability
  • All client traffic funnels into one App Insights instance
  • Token usage tracked across every caller with llm-emit-token-metric
  • APIM request logs correlated with OTel traces via operation_Id
  • Single dashboard for latency, errors, and cost across all services
⚡ Traffic Control
  • Token-per-minute limits per subscription (llm-token-limit)
  • Rate limiting prevents quota exhaustion
  • Retry and circuit-breaker policies in one place
  • Load-balance across multiple Azure OpenAI regions
🔧 Governance & Flexibility
  • Swap Azure OpenAI deployments without touching client code
  • URL rewrite keeps client endpoint stable across model upgrades
  • Developer portal provides self-service key management
  • Works with any OpenAI-compatible SDK — no vendor lock-in
