Overview

Why capture Claude Code telemetry?

Claude Code emits rich OpenTelemetry signals when enabled — giving you visibility into every AI interaction, tool invocation, and spend that would otherwise be invisible.

What you getWhy it matters
Token counts per requestTrack consumption and forecast cost per developer or team
Cost in USD per requestClaude Code reports cost_usd directly — no estimation needed
Tool call detailsSee which tools (bash, edit, search) Claude invoked and how often
User promptsCapture the actual questions developers ask for quality review
Cache token usageUnderstand cache hit rates and savings from prompt caching
Model versionTrack which Claude model version handled each request
Architecture

How the telemetry flows

Claude Code reads its OTel configuration from .claude/settings.json (workspace) or from environment variables. It exports logs and metrics over OTLP HTTP to the collector, which forwards them to Azure Monitor.

Pre-requisite: The OpenTelemetry Collector from sample 20 must be running and listening on http://localhost:4318 before you start using Claude Code.

Configuration — Option 1

Workspace settings: .claude/settings.json

Create or edit .claude/settings.json at the root of your workspace. Settings here apply to everyone who opens this project with Claude Code.

{
  "env": {
    "CLAUDE_CODE_ENABLE_TELEMETRY": "1",
    "OTEL_METRICS_EXPORTER":        "otlp",
    "OTEL_LOGS_EXPORTER":           "otlp",
    "OTEL_EXPORTER_OTLP_PROTOCOL":  "http/protobuf",
    "OTEL_EXPORTER_OTLP_ENDPOINT":  "http://localhost:4318",
    "OTEL_LOG_USER_PROMPTS":        "1",
    "OTEL_LOG_TOOL_DETAILS":        "1",
    "OTEL_METRICS_INCLUDE_VERSION":  "true"
  }
}

Tip: Commit this file to source control so the whole team shares the same telemetry configuration automatically.

Configuration — Option 2

Environment variables via PowerShell

Set variables at User scope — they persist across sessions and apply to all workspaces. Restart your terminal or Claude Code after setting them.

# Set Claude Code OTel env vars for current user
$vars = @{
    "CLAUDE_CODE_ENABLE_TELEMETRY" = "1"
    "OTEL_METRICS_EXPORTER"        = "otlp"
    "OTEL_LOGS_EXPORTER"           = "otlp"
    "OTEL_EXPORTER_OTLP_PROTOCOL"  = "http/protobuf"
    "OTEL_EXPORTER_OTLP_ENDPOINT"  = "http://localhost:4318"
    "OTEL_LOG_USER_PROMPTS"        = "1"
    "OTEL_LOG_TOOL_DETAILS"        = "1"
    "OTEL_METRICS_INCLUDE_VERSION"  = "true"
}

foreach ($key in $vars.Keys) {
    [System.Environment]::SetEnvironmentVariable($key, $vars[$key], "User")
}
Settings Reference

What each variable does

VariableDescription
CLAUDE_CODE_ENABLE_TELEMETRYMaster switch. Set to 1 to enable all OTel export. Remove or set to 0 to disable.
OTEL_METRICS_EXPORTERotlp sends metrics (token counts, cost, duration) to the collector.
OTEL_LOGS_EXPORTERotlp sends log records (API requests, tool calls) to the collector.
OTEL_EXPORTER_OTLP_PROTOCOLhttp/protobuf — use HTTP with Protobuf encoding (port 4318).
OTEL_EXPORTER_OTLP_ENDPOINTURL of your OTel Collector. Default is http://localhost:4318.
OTEL_LOG_USER_PROMPTSWhen 1, includes the actual prompt text in log records. Useful for quality review.
OTEL_LOG_TOOL_DETAILSWhen 1, logs details of every tool call (bash commands, file edits, searches).
OTEL_METRICS_INCLUDE_VERSIONIncludes the Claude model version tag on every metric.

Observability Output

What you see in Application Insights

Log record
claude_code.api_request
One record per model call. Contains all token counts, cost_usd, model version, and prompt if enabled.
Dimension
cost_usd
Exact cost in USD for the request as reported by Claude. No estimation needed.
Dimension
input_tokens / output_tokens
Token counts for the prompt and completion. Enables per-developer usage tracking.
Dimension
cache_creation_tokens
Tokens written to the prompt cache. Shows where caching is active.
Dimension
cache_read_tokens
Tokens read from the prompt cache. Higher values = more cost savings.
Dimension
user.email
The authenticated developer's email — enables per-user reporting in KQL.
Log Analytics / KQL

Useful queries

All Claude Code API calls — tokens, cost, and prompt
traces
| where message == "claude_code.api_request"
| extend cost_usd_     = todecimal(customDimensions.cost_usd)
| extend inputTokens_  = tolong(customDimensions.input_tokens)
| extend outputTokens_ = tolong(customDimensions.output_tokens)
| extend userEmail_    = tostring(customDimensions["user.email"])
| extend model_        = tostring(customDimensions.model)
| project timestamp, userEmail_, model_, cost_usd_, inputTokens_, outputTokens_
| order by timestamp desc
Cost per developer · last 7 days
traces
| where message == "claude_code.api_request"
| where timestamp > ago(7d)
| extend cost_    = todecimal(
    customDimensions.cost_usd)
| extend email_   = tostring(
    customDimensions["user.email"])
| summarize
    TotalCostUSD = sum(cost_),
    Requests     = count()
    by email_
| order by TotalCostUSD desc
Cache savings · input vs cache read
traces
| where message == "claude_code.api_request"
| extend cacheRead_ = tolong(
    customDimensions.cache_read_tokens)
| extend cacheNew_  = tolong(
    customDimensions.cache_creation_tokens)
| summarize
    TotalCacheRead    = sum(cacheRead_),
    TotalCacheCreated = sum(cacheNew_)
    by bin(timestamp, 1d)
| order by timestamp desc
