The Problem

The per-machine Windows service doesn't scale across a team

Install on every machine
The Windows service approach requires every developer to install and configure the OTel Collector locally
Configuration drift
Connection string changes, exporter tweaks, or version upgrades need to be repeated on every dev machine
No shared control
No central place to pause, rotate keys, or update the pipeline for the whole team at once
Goal: keep the same collector, the same config approach, and the same Application Insights destination — but host the collector once, centrally, in Azure.

Setup · Step 1

Deploy Log Analytics, App Insights & the Container Apps Environment

# Log Analytics workspace
az monitor log-analytics workspace create -g rg-otel-collector -n law-otel-collector

# App Insights, workspace-based, pointing at the workspace above
az monitor app-insights component create -g rg-otel-collector -a appi-otel-collector -l uksouth \
  --workspace law-otel-collector

# Container Apps Environment to host the collector
az containerapp env create -g rg-otel-collector -n cae-otel-collector -l uksouth
Application Insights is workspace-based — every table it collects (dependencies, traces, customMetrics) is queryable directly from the Log Analytics workspace too.
Setup · Step 2

Package the collector as a container image

Same config.yaml approach as the Windows service, but the connection string now comes from an environment variable so it can be injected as a Container Apps secret:

Dockerfile
FROM otel/opentelemetry-collector-contrib:0.157.0
COPY config.yaml /etc/otelcol-contrib/config.yaml
Build & push to ACR
az acr create -g rg-otel-collector -n acrotelcollector --sku Basic
az acr build -r acrotelcollector -t otel-collector:0.157.0 .
config.yaml exporter
exporters:
  azuremonitor:
    connection_string: "${env:APPINSIGHTS_CONNECTION_STRING}"
    maxbatchsize: 1024
    maxbatchinterval: 10s
    spaneventsenabled: false
Nothing sensitive is baked into the image — the connection string is resolved from the environment at container start.
Setup · Step 3

Deploy the collector as a Container App

az containerapp create \
  -g rg-otel-collector -n ca-otel-collector \
  --environment cae-otel-collector \
  --image acrotelcollector.azurecr.io/otel-collector:0.157.0 \
  --registry-server acrotelcollector.azurecr.io \
  --target-port 4318 --ingress external \
  --secrets appinsights-connection-string="<CONNECTION-STRING>" \
  --env-vars APPINSIGHTS_CONNECTION_STRING=secretref:appinsights-connection-string \
  --min-replicas 1 --max-replicas 1
Ingress
Target port 4318 exposes OTLP/HTTP; Container Apps terminates TLS so clients call over HTTPS on 443
OTLP/gRPC (4317) also works, but needs ingress transport set to http2
Config & scale
--min-replicas 1 keeps a warm instance so telemetry isn't dropped while scaling
Rotating the connection string is one az containerapp secret set — no per-machine changes
Setup · Step 4

Point VS Code at the container app endpoint

Same GitHub Copilot / Claude Code OpenTelemetry settings as the Windows service sample — only the endpoint changes:

Before — Windows service
http://localhost:4318
Requires the collector installed on this machine
After — Container App
https://ca-otel-collector.<region>.azurecontainerapps.io
Same URL for every developer — nothing to install locally
Because the endpoint is a shared, public HTTPS URL, updates to the collector — new exporter settings, upgraded version, rotated connection string — reach every developer instantly without touching a single dev machine.
Verify

Same verification, same Application Insights tables

# Tail the collector's logs
az containerapp logs show -g rg-otel-collector -n ca-otel-collector --follow
Table What it contains
dependencies Each LLM call as a dependency span — model, duration, status
traces Log messages emitted during AI operations
customMetrics Token counts — gen_ai.client.token.usage
Trigger a Copilot or Claude Code action in VS Code and confirm the event appears in App Insights → Transaction Search within ~30 seconds — the existing KQL queries and Workbooks from sample 20 work unchanged.
