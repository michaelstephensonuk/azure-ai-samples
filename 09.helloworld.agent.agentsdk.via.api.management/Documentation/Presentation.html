Architecture

How APIM routing works with MAF

// App builds an OpenAIClient pointing at the APIM gateway
HttpClient httpClient = new HttpClient();
httpClient.DefaultRequestHeaders.Add(
    "Ocp-Apim-Subscription-Key", apimSubscriptionKey);

OpenAIClientOptions opts = new()
{
    Endpoint  = new Uri(apimGatewayUrl),
    Transport = new HttpClientPipelineTransport(httpClient)
};

// SDK credential is a placeholder — real auth lives in APIM
AIAgent agent = new OpenAIClient(new ApiKeyCredential("placeholder"), opts)
    .GetChatClient(deploymentName)
    .AsIChatClient()
    .AsBuilder()
    .UseOpenTelemetry(o => o.EnableSensitiveData = true)
    .Build()
    .AsAIAgent(instructions: systemPrompt, name: "...", tools: [...]);
Why OpenAIClient not AzureOpenAIClient? The Azure client appends /openai/deployments/{name}/chat/completions to the base URL. APIM exposes a simpler path like /chat/completions. Using OpenAIClient means the SDK sends exactly the path that APIM's operation is mapped to.

Security

Security benefits of routing via APIM

Key isolation
The real Azure OpenAI api-key is stored in the APIM policy, not in any app config file
Rotating the OpenAI key requires updating one APIM policy — no app redeployment
Governance & quotas
Rate limiting, token quotas, and usage tracking applied centrally at APIM
Multiple apps share one APIM subscription layer with different policies
Auditability
APIM logs every call with subscription ID — who called what and when
Works alongside the app-level App Insights telemetry for end-to-end tracing
Same security posture as sample 06 — sample 09 inherits all of these benefits without any additional configuration. The MAF abstraction layer is transparent to APIM.
Takeaways

Why this sample exists

Use sample 09 when…
You want the clean AIAgent abstraction of MAF and the governance of APIM
Your organisation requires that apps never hold Azure OpenAI keys
You're adopting Microsoft Agent Framework on an existing APIM-gated Azure OpenAI setup
You want a path toward multi-agent orchestration without giving up your APIM policy layer
When other samples may be better
No APIM available or needed → use sample 07 (MAF direct)
Need full ME.AI composability (custom middleware) → use sample 06 (ME.AI + APIM)
Simplest possible baseline → use sample 05 (ME.AI direct)
Sample 09 is the production-ready combination: MAF's ergonomic agent API plus APIM's security and governance layer.
